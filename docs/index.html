A queue for parallel coding agents

Heavy commands take turns. The machine stays calm.

calmrun is a machine-wide queue for tests, type checks, builds and docker. Put calmrun -- in front of a heavy command and it waits until the machine has room, then runs it at low CPU priority and passes its exit code back. Several coding agents and terminals can share one computer without freezing it.

The problem

One test run is fine. Four agents that each start vitest with a worker per core, plus a tsc and a build, are not: they all start in the same minute, and nobody is in charge of the machine.

Everything starts at once

Each agent decides on its own to run the tests, the type check and the build. None of them knows the others are doing the same.

The machine stalls

RAM runs out and the system swaps. The editor, the terminal and the agents themselves stop responding.

Tests time out

Starved runs fail on timeouts that have nothing to do with the code. Agents retry, which adds even more load.

How it works

Every calmrun process adds its job to a small state file guarded by an OS file lock, and every waiter applies the same rules to it. There is no daemon to start or keep alive.

Points by kind

calmrun reads the command and picks a kind: vitest, jest, type checks and builds cost 2 points, monorepo runners 3, linters, plain test runs and a single compiler call 1. --cost and --kind override it, and your own kinds go in the config.

RAM and disk gates

A job also waits while free RAM is below min_free_gb or its drive has less than min_free_disk_gb free. On an idle machine it starts anyway, so nothing waits forever.

One run per folder

vitest, jest and JavaScript builds take their nearest node_modules, Cargo its target folder, and Gradle, Maven, .NET, CMake, Swift or Flutter builds their project folder. Two jobs on the same folder never run together, so caches and build output don't fight.

Low priority, bounded memory

Commands run below normal priority (nice +10 on Unix), so your editor stays responsive. A job whose process tree goes above ceiling_gb is stopped with exit 137.

No endless commands

Watch modes (vitest watch, tsc -w, gradle -t, dotnet watch, …) and attached docker compose up would hold points forever, so calmrun refuses them and prints the one-shot command to run instead. Dev servers and app runs start at once, outside the queue.

Tickets, resources, queues

--wait-timeout gives up after a while (exit 75) and keeps the place in line for 10 minutes as a ticket. --needs db takes a named resource; --id uses a separate queue.

Agent integration

Agents don't need to remember anything: hooks for Claude Code, Codex and OpenCode (Antigravity: experimental) catch heavy shell commands, the MCP server gives any MCP client a queued run_task tool, and setup writes the instructions and hooks into each agent's global files.

Agent hooks

calmrun hook claude|codex|opencode|antigravity is a PreToolUse hook for the agent's shell tool. When a command runs a heavy tool without calmrun (also through rtk), the hook denies it and tells the agent the exact command with each heavy part wrapped, with a --wait-timeout below the tool's time limit. Light commands pass. calmrun setup --write --hook all installs them; for Claude Code by hand, in ~/.claude/settings.json: 

{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash|PowerShell",
        "hooks": [{ "type": "command", "command": "calmrun hook claude" }]
      }
    ]
  }
}

cd web && npx vitest run becomes cd web && calmrun -- npx vitest run. With CALMRUN_HOOK_MODE=rewrite the hook rewrites the command itself instead of denying it.

MCP server

calmrun mcp serves tools over stdio: run_task (waits in the same queue and runs the command; a job still busy after wait_seconds goes on in the background and returns a task_id), task_status, cancel_task, queue_status and bump. For a device or an emulator without a command: calmrun hold emulator prints a lease, calmrun release <lease> gives it back. 

# Claude Code
claude mcp add calmrun -- calmrun mcp

# Codex: ~/.codex/config.toml
[mcp_servers.calmrun]
command = "calmrun"
args = ["mcp"]
tool_timeout_sec = 3600

// Cursor: ~/.cursor/mcp.json
{ "mcpServers": { "calmrun": { "type": "stdio", "command": "calmrun", "args": ["mcp"] } } }

// Gemini CLI: ~/.gemini/settings.json (timeout in ms)
{ "mcpServers": { "calmrun": { "command": "calmrun", "args": ["mcp"], "timeout": 3600000 } } }

calmrun setup

Adds a short calmrun section to the global instruction file of Claude Code, Codex, Gemini CLI and OpenCode. It is a dry run until you add --write; every file it changes is backed up first. 

$ calmrun setup                          # show what would change
$ calmrun setup --write                  # apply
$ calmrun setup --write --agents codex   # only some agents
$ calmrun setup --write --hook           # also the Claude Code hook (--hook all: every agent)
$ calmrun setup --write --remove --hook  # take both out again

calmrun guide

Prints short instructions to paste into an agent's context. Or add this to CLAUDE.md or AGENTS.md by hand: 

## Heavy commands

This machine is shared by several agents. Run heavy commands
through the calmrun queue: `calmrun -- <command>` (tests, type
checks, linters, builds, Playwright, docker compose, pytest,
cargo/gradle/make/dotnet/go builds).
Example: `calmrun -- npx vitest run`.
Run anything that may take more than a minute or two in the
background and check on it later.
Use `calmrun status` to see what is running or waiting.
Do not wrap light commands (git, ls, cat, package installs).

Commands

calmrun [flags] -- <cmd> Queue the command, then run it at low priority. Flags: --kind, --cost N, --prio high|low, --label L, --needs db,gpu, --id QUEUE, --wait-timeout SECS, --ticket ID, --timeout SECS, --log. One quoted string runs through the shell.
calmrun statusWhat runs, what waits and why, the budget and free RAM; for a running job its CPU, how long it has been idle, its usual time and its last output. --json for tools.
calmrun statsRuns, failures, wait and run times per label over --days N (default 7).
calmrun bump <label>Move waiting jobs to the front, where later jobs may not pass them while they wait for room; pick them by label, --pos N, --ticket ID or --dir PATH. --back moves them to the end.
calmrun stop <id>Stop a running or waiting job (the id column of status, or --label); a calmrun that does not react is killed.
calmrun logs <id>The output of a job that keeps a log (MCP tasks, runs with --log): --tail N, --follow.
calmrun doctorCores, RAM, disk, battery, where state lives, and the suggested config.
calmrun initWrite a commented config.toml with this machine's defaults (--force overwrites).
calmrun guideShort instructions for coding agents.
calmrun setupWrite or remove the calmrun block in agents' global instruction files: --write, --remove, --hook, --agents.
calmrun hold / releaseHold a resource slot (an emulator, a database) without a command and print a lease; release <lease> gives it back, release --ticket <id> gives up a kept place.
calmrun hook <agent>The PreToolUse hook of claude, codex, opencode or antigravity (experimental); reads the hook JSON on stdin.
calmrun mcpThe MCP server on stdio: run_task, task_status, cancel_task, queue_status, bump.

Exit codes

the command's ownit ran (a Unix signal n becomes 128 + n)
2refused (watch mode, attached docker compose up), bad arguments or an invalid --id
75not started within --wait-timeout; the place is kept, run the printed calmrun: next: line
124stopped by its run time limit: --timeout, MCP timeout_s or max_run_min (60 min for test-like kinds)
126 · 127the command could not be started · was not found
130Ctrl+C or calmrun stop
137stopped by the memory ceiling or the critical free-RAM floor

Config and environment

Every setting is optional. calmrun init writes a commented config.toml in the state directory; an environment variable wins over the file.

Platform notes

  • Windows: where calmrun is built, and checked by hand on a real machine as well as in CI. npm, npx and other .cmd shims work; the command runs in a Job Object, so its whole tree ends if calmrun is killed.
  • macOS and Linux: covered by the test suite in CI (GitHub's macOS and Ubuntu runners), not checked by hand yet. The command gets its own process group with nice +10 and dies with calmrun.
  • Release binaries are built for x64 and arm64 on all three systems. CI runs the tests on Windows x64, Linux x64 and macOS arm64 only; the other builds are not tested.
  • Memory is counted as resident memory per process (working set on Windows, RSS elsewhere); shared pages count more than once, so a tree's total can read high.
  • Ctrl+Z and handing the terminal over are not covered by CI, because CI runners have no terminal.

Install

One binary, no runtime. The installers put calmrun in ~/.cargo/bin (%USERPROFILE%\.cargo\bin on Windows) and add it to PATH; open a new terminal afterwards.

macOS / Linux

curl --proto '=https' --tlsv1.2 -LsSf https://github.com/vannt-dev/calmrun/releases/latest/download/calmrun-installer.sh | sh

Windows (PowerShell)

powershell -ExecutionPolicy Bypass -c "irm https://github.com/vannt-dev/calmrun/releases/latest/download/calmrun-installer.ps1 | iex"

npm (any OS)

npm install -g calmrun

From source (Rust 1.95 or newer)

cargo install calmrun --locked

Manual download

From Releases: calmrun-x86_64-pc-windows-msvc.zip, calmrun-aarch64-pc-windows-msvc.zip, calmrun-x86_64-apple-darwin.tar.xz, calmrun-aarch64-apple-darwin.tar.xz, calmrun-x86_64-unknown-linux-gnu.tar.xz, calmrun-aarch64-unknown-linux-gnu.tar.xz, each with a .sha256. Unpack and put the binary on PATH.

First steps

$ calmrun doctor                  # what this machine has, the suggested budget

$ calmrun "npm ci && npm test"    # one quoted string runs in the shell
